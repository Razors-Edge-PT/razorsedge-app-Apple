### 4. Implementation Steps

#### Step 1 â€” Verify Firestore template path (read-only)
Read `lib/templates.dart` to confirm the collection path (expected: `/planned_blocks/{uid}/blocks/{blockId}/templates/{docId}` or `/users/{uid}/templates/{docId}`) and the exercise map fields. Record the exact path before writing any service code.

#### Step 2 â€” Verify BB3 planned-day clear method (read-only)
Read `lib/WES2_repository.dart` to check whether a method for clearing/writing the BB3 planned-day path (`/planned_blocks/{uid}/blocks/{blockId}/weeks/week_{n}/days/day_{n}`) already exists. If it does not exist, the template load will **print `BLOCKED: BB3 clear path not verified`** in a debug assertion and skip the BB3 clear rather than guessing. The clear is deferred to a future phase.

#### Step 3 â€” Implement `FirestoreWes2TemplateService` in `WES2_template_service.dart`
- `loadTemplate(uid, templateId)`:
  - Reads template document from the verified Firestore path.
  - Maps each exercise entry to a `Wes2ExerciseRow` with `source: Wes2RowSource.templateLoaded`, blank `sets` (empty `Wes2SetState` list sized to stored `setCount`), `isMarkedDone: false`.
  - Returns the row list ordered by `(circuitIndex, orderIndex)`.
  - Does **not** populate any actual values or hint values.
- `saveWorkoutAsTemplate(uid, blockId, templateName, rows)`:
  - Filters to rows that meet save eligibility (see Step 5 controller method).
  - Builds a structure-only map per row: `{ exerciseId, name, circuitIndex, orderIndex, setCount }`.
  - Writes a new document to the verified template collection with `{ name: templateName, blockId, exercises: [...] }`.
  - Does **not** write `weight`, `reps`, `rir`, `sets[]` actual values, `isMarkedDone`, hints, plan notes, or execution notes.

#### Step 4 â€” Add controller methods in `WES2_controller.dart`
- `_loadedFromTemplate`: new `bool` field, initialised to `false`, reset to `false` in `changeDate()`.
- `loadTemplate(templateId, Wes2TemplateService service)` method:
  1. `_pushUndo()` â€” snapshot current `_rows` onto undo stack before any mutation.
  2. `await service.loadTemplate(uid, templateId)` â†’ `incomingRows`.
  3. Build a deduped merged list:
     - Start with the existing `_rows` date's exerciseIds as a `Set<String> existingIds`.
     - For each `incomingRow` (in template order): if `existingIds` contains `incomingRow.exerciseId`, skip (silent dedupe); otherwise add to result and to `existingIds`.
  4. Assign final merged list to `_rows`, renumber `orderIndex` globally.
  5. Set `_loadedFromTemplate = true`.
  6. Notify listeners (call `notifyListeners()`).
  7. BB3 clear: if `_activeBlockId` is non-null, week/day indices are known, and the repository exposes a verified BB3 clear method: call it tightly scoped to `(blockId, weekIndex, dayIndex)` only. Otherwise print `BLOCKED: BB3 clear not verified` and proceed without clearing.
- `canSaveAsTemplate` getter:
  - Returns `true` only when: `!_loadedFromTemplate`, at least one row is present, and every row has `isMarkedDone == true`.
  - Conservative gate; returns `false` if uncertain.
- `saveAsTemplate(String name, String blockId, Wes2TemplateService service)`:
  - Guards on `canSaveAsTemplate`; no-ops if `false`.
  - Calls `service.saveWorkoutAsTemplate(uid, blockId, name, _rows)`.

#### Step 5 â€” Create `WES2_widgets/WES2_template_picker.dart`
- A `showWes2TemplatePicker(context, uid, onTemplateSelected)` function that shows a `DraggableScrollableSheet` bottom sheet.
- Loads templates via the `Wes2TemplateService` (passed as dependency).
- Layout rules (overflow blockers):
  - Each list tile uses a `Row` with the template name inside `Expanded(child: Text(..., maxLines: 1, overflow: TextOverflow.ellipsis))`.
  - Block label badge uses `Flexible` if rendered inline.
  - No `ListTile` inside `PopupMenuItem`.
  - All `Row` children with unbounded text use `Expanded` or `Flexible`.
- Calls `onTemplateSelected(templateId)` when user taps a template.
- "Cancel" button closes sheet without selection.

#### Step 6 â€” Wire into `WES2_screen.dart`
- Add a **"Load Template"** action to the day-level 3-dot menu (near the Select Date area). Tapping calls `showWes2TemplatePicker(...)`. On selection, calls `controller.loadTemplate(templateId, service)`. If rows were replaced (non-empty prior state), show a snackbar with Undo. If day was empty, no snackbar.
- Add a **"Save workout to templates"** `TextButton` label below the exercise list, visible only when `controller.canSaveAsTemplate == true`. Tapping opens a small dialog (name field + Save button). On save, calls `controller.saveAsTemplate(name, blockId, service)`.
- No other screen structural changes.

#### Step 7 â€” Add tests in `test/wes2/WES2_template_test.dart`
- `loadTemplate dedupes duplicate exerciseIds`: mock service returns two rows with the same `exerciseId`; controller ends up with exactly one.
- `loadTemplate pushes undo before replacing rows`: verify undo stack depth increases by 1 and undo restores prior rows.
- `saveWorkoutAsTemplate strips actual values`: verify saved exercise maps contain no `weight`/`reps`/`rir`/`isMarkedDone` keys.
- `canSaveAsTemplate is false when loadedFromTemplate`: set `_loadedFromTemplate = true`, verify getter returns `false`.

### 6. Continuity Protections

- **Selected date/session**: `changeDate()` resets `_loadedFromTemplate` flag; no other change.
- **Local draft/fast reopen**: Isar `saveDraft`/`loadDraft` unchanged; template-loaded rows have `source: templateLoaded` so they persist via existing `wesPlannedExercises[]` save path.
- **Undo stack continuity**: `_pushUndo()` called before template replace; existing undo for add/delete/replace/move/reorder is not touched.
- **Add Exercise / Add Circuit / Add Set / Remove Set / Delete / Replace / Move / Done**: none of these code paths are modified.
- **Duplicate exerciseId prevention across the date**: existing `addExercise()` set-guard is unchanged; template load applies the same guard via the new dedupe loop in `loadTemplate()`.
- **No current-WES edits**: `lib/workout_entry_screen.dart` not touched.
- **No BB3 file edits**: `lib/bb3_*.dart` not touched; BB3 planned-day clear (if applicable) goes through the WES2 repository only and is gated behind a `BLOCKED` assertion if the method is not verified.
- **No PMU / progression modifications**: none.

### 7. Phase 18 Template-Specific Statements

- Template load is a **WES2-only extension**, not an architecture restart.
- Template load calls `_pushUndo()` and snapshots the current `_rows` before replacing them.
- Template load dedupes duplicate `exerciseId`s silently, keeping the first valid row in template order.
- Template load replaces the current WES2 day rows only, as specified by the WES2 template contract; it does not append.
- Save-as-template stores structure only (`exerciseId`, `name`, `circuitIndex`, `orderIndex`, `setCount`); actual logged values, hints, notes, and `isMarkedDone` are never saved into a template.
- `lib/templates.dart` and `lib/template_model.dart` are inspected read-only for schema; they are not edited.
- All blocked/reference files are not edited.

### 10. Risks and Overflow Guards

| Risk | Mitigation |
|------|-----------|
| Template Firestore path unknown until `templates.dart` is read | Step 1 is a mandatory read before any service write; if path is ambiguous, print `BLOCKED` |
| BB3 clear method absent from repository | BLOCKED guard in controller; clear is skipped, not guessed |
| Long template names overflow picker row | All Row text in picker wrapped in `Expanded(child: Text(..., maxLines: 1, overflow: TextOverflow.ellipsis))` |
| Block label badge overflows if rendered inline | Wrapped in `Flexible` |
| PopupMenuItem content â€” spec forbids ListTile inside | Picker uses custom `InkWell`/`Padding` row, not `ListTile` in `PopupMenuItem` |
| `canSaveAsTemplate` shown prematurely | Conservative gate: `!_loadedFromTemplate && rows.isNotEmpty && rows.every((r) => r.isMarkedDone)` |
| Dedupe fails on concurrent add + template load | Template `loadTemplate` uses same `Set<String>` guard as `addExercise`; no race window because controller is single-threaded notification model |
