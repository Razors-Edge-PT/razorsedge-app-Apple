#### 2. `lib/WES2_plan_service.dart` â€” MODIFY (implement `updatePlannedDay` stub)

**Current state**: `updatePlannedDay` throws `UnimplementedError`.

**Change**: Implement to support BB3 planned day clearing.

```
@override
Future<void> updatePlannedDay({uid, blockId, weekIndex, dayIndex, updatedRows}) async {
  final docRef = FirebaseFirestore.instance
      .collection('planned_blocks').doc(uid)
      .collection('blocks').doc(blockId)
      .collection('weeks').doc('week_$weekIndex')
      .collection('days').doc('day_$dayIndex');
  final exercisesList = updatedRows.map((r) => {
    'exerciseId': r.exerciseId,
    'name': r.name,
    'circuitIndex': r.circuitIndex,
    'orderIndex': r.orderIndex,
    'setCount': r.setCount,
  }).toList();
  await docRef.update({'exercises': exercisesList});
}
```

When called with `updatedRows: []`, this writes `{'exercises': []}`, clearing the BB3 planned day. Uses `update()` (not `set()`), so all other fields on the document (day name, notes, metadata) are preserved.

**Guard**: This method is only called from `WES2_screen.dart` and only when `_controller.rows.any((r) => r.source == Wes2RowSource.bb3Planned)` is true at the moment the user loads a template. Only the current `blockId`/`weekIndex`/`dayIndex` values from `_controller.blockContext` are used â€” never other days.

#### 3. `lib/WES2_repository.dart` â€” MODIFY (add `saveTemplateLoad` method)

**Confirmed in-scope**: `lib/WES2_repository.dart` matches `lib/WES2_*.dart`. File already exists in the repo.

**Reason**: When a template is loaded, blank `templateLoaded` rows must be persisted to Firestore's `wesPlannedExercises[]` so they survive a full cold reopen. The existing `saveManualExercise` is designed for single-row adds. Calling it in a loop for 10 exercises would require 10 separate Firestore transactions. A single `saveTemplateLoad` is safer and atomic.

**Change**: Add to abstract interface and `FirestoreWes2Repository`:

```dart
/// Replace the wesPlannedExercises[] array for a given date with the
/// provided templateRows. Called only when loading a template.
Future<void> saveTemplateLoad({
  required String uid,
  required DateTime date,
  required List<Wes2ExerciseRow> templateRows,
});
```

Implementation writes the full `wesPlannedExercises` array (replacing previous contents) to the workout document for `date`. It does NOT touch `exercises[]`. Uses `update({'wesPlannedExercises': [...]})`.

The write doc path is the same path already used by existing repository methods for the same `uid`/`date` combination (confirmed by reading the existing `saveManualExercise` implementation in the file).

**Add `_onLoadTemplate()` method:**

```
Future<void> _onLoadTemplate() async {
  // 1. Open Wes2TemplatePicker bottom sheet
  final result = await showModalBottomSheet(...)
  if (result == null) return;
  
  // 2. Determine if current day has BB3-sourced rows
  final hasBb3Rows = _controller.rows.any(
      (r) => r.source == Wes2RowSource.bb3Planned);
  
  // 3. Determine if current day is non-empty (for undo snackbar)
  final wasEmpty = _controller.rows.isEmpty;
  
  // 4. Load template rows from service
  final templateRows = await _templateService.loadTemplate(
      uid: _controller.actingUid,
      templateId: result.templateId);
  
  // 5. Deduplicate against already-completed exercises on this date
  //    (completed rows remain; template rows skipped if exerciseId matches)
  final completedIds = _controller.rows
      .where((r) => r.source == Wes2RowSource.completedServer)
      .map((r) => r.exerciseId)
      .toSet();
  final dedupedRows = templateRows
      .where((r) => !completedIds.contains(r.exerciseId))
      .toList();
  
  // 6. Replace rows in controller (pushes undo, sets originatedFromTemplate)
  _controller.loadTemplate(dedupedRows);
  
  // 7. Persist template rows to Firestore wesPlannedExercises[]
  _saveTemplateLoadSilently(dedupedRows);
  
  // 8. Clear BB3 planned day if it had BB3-sourced rows
  if (hasBb3Rows) {
    _clearBb3PlannedDaySilently();
  }
  
  // 9. Save draft
  _saveDraftNow();
  
  // 10. Show undo snackbar if day was non-empty before load
  if (!wasEmpty) {
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: Text('Replaced with "${result.templateName}"'),
        action: SnackBarAction(label: 'UNDO', onPressed: _onUndo),
      ),
    );
  }
}
```

**Add `_saveTemplateLoadSilently()`**: Fire-and-forget call to `_repository.saveTemplateLoad(...)`. Swallows errors.

**Add `_clearBb3PlannedDaySilently()`**: Fire-and-forget call to `_planService.updatePlannedDay(updatedRows: [])` with current `blockContext` values (`blockId`, computed `weekIndex`/`dayIndex` from `_weekDayFromDate()`). Swallows errors. No offline queue.

**Add `_onSaveWorkoutAsTemplate()` method** (triggered from `Wes2BottomActionsRow`):
- Show a dialog with a `TextField` for template name (pre-filled with e.g. "Day X" or empty).
- On confirm, call `_templateService.saveWorkoutAsTemplate(...)` with the current rows.
- Show a snackbar on success ("Saved to templates").
