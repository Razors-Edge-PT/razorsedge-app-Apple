### 1. BB3 Clear Write Shape â€” Verified NOT BLOCKED

From the current `FirestoreWes2PlanService.loadPlannedDay`, the BB3 day path is:

```
/planned_blocks/{uid}/blocks/{blockId}/weeks/week_{weekIndex}/days/day_{dayIndex}
```

The document field is `exercises: List<dynamic>`. Clearing means writing `{exercises: []}` to that same document path via `doc.update({'exercises': []})`.

`updatePlannedDay(updatedRows: [])` serialises to exactly that â€” the same shape already consumed by `loadPlannedDay`. **Write shape is known and safe. NOT BLOCKED.**

The `updatePlannedDay` stub already exists in the interface (`WES2_plan_service.dart:186`). We only need to implement it.

### 3. Files to MODIFY

#### `lib/WES2_template_service.dart` â€” MODIFY (replace stub, add concrete class)

Keep the `abstract class Wes2TemplateService` unchanged.

Add concrete class `FirestoreWes2TemplateService implements Wes2TemplateService`:

**`loadTemplate({uid, templateId})`**

1. Fetch the template document from Firestore (path from `templates.dart`).
2. Parse using `Template.fromFirestore(data, docId)`.
3. Convert `template.exercises` to `List<Wes2ExerciseRow>`:
   - Each exercise map: `{id/exerciseId â†’ exerciseId, name, circuitIndex (default 0), orderIndex (fallback to list index)}`
   - Construct `Wes2ExerciseRow(exerciseId: ..., name: ..., circuitIndex: ..., orderIndex: ..., setCount: 3, sets: const [], source: Wes2RowSource.templateLoaded)`
   - **No hint values** â€” template rows carry no planned weights/reps.
   - Deduplicate within the list by `exerciseId`: if the same `exerciseId` appears twice in the template itself, keep only the first occurrence (silently skip).
4. Sort by `circuitIndex` then `orderIndex`.
5. Return the list. Throws if the document does not exist (caller handles).

**`saveWorkoutAsTemplate({uid, blockId, templateName, rows})`**

1. Build the exercises list: for each row in `rows`, emit `{id: row.exerciseId, name: row.name, circuitIndex: row.circuitIndex, orderIndex: row.orderIndex}`. **Never include weight, reps, rir, velocity, or any actual values.**
2. Write to Firestore (same collection path): `{name: templateName, blockId: blockId, exercises: [...]}`. Use `.add()` (auto-ID).
3. Throws on failure; caller catches and shows snackbar.

**New method `loadTemplateRows`:**
```dart
/// Replaces all current rows with [templateRows].
/// Caller must have already deduplicated templateRows by exerciseId.
/// Pushes undo before replacing.
/// Returns the previous rows so caller can decide whether to show snackbar.
List<Wes2ExerciseRow> loadTemplateRows(List<Wes2ExerciseRow> templateRows) {
  final previous = List<Wes2ExerciseRow>.from(_rows);
  _pushUndo();
  _rows = templateRows;
  _templateLoadedThisSession = true;
  _loadState = templateRows.isEmpty ? Wes2LoadState.empty : Wes2LoadState.loaded;
  notifyListeners();
  return previous;
}
```

#### `lib/WES2_plan_service.dart` â€” MODIFY (implement `updatePlannedDay`)

Implement `FirestoreWes2PlanService.updatePlannedDay`:

```dart
@override
Future<void> updatePlannedDay({
  required String uid,
  required String blockId,
  required int weekIndex,
  required int dayIndex,
  required List<Wes2ExerciseRow> updatedRows,
}) async {
  final exercises = updatedRows.map((r) => {
    'exerciseId': r.exerciseId,
    'name': r.name,
    'circuitIndex': r.circuitIndex,
    'orderIndex': r.orderIndex,
  }).toList();
  await FirebaseFirestore.instance
      .collection('planned_blocks')
      .doc(uid)
      .collection('blocks')
      .doc(blockId)
      .collection('weeks')
      .doc('week_$weekIndex')
      .collection('days')
      .doc('day_$dayIndex')
      .update({'exercises': exercises});
}
```

Passing `updatedRows: []` produces `{exercises: []}` which clears the BB3 day.
